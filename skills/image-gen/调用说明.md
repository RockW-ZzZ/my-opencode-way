# APIKEY.FUN `image-gen` Skill 调用说明

## 1. 功能

本 Skill 通过 `api.apikey.fun` 完成：

- 文生图：根据文字生成图片。
- 图生图：以一张本地图片或网络图片作为参考生成新图片。
- 图片编辑：修改现有图片，并尽量保留原有内容。
- 视频生成：支持文生视频和图生视频。
- 常见任务：替换背景、透明背景、风格转换、产品图优化、尺寸生成等。

图片请求使用 `stream=true`；视频使用异步提交和状态轮询。每次生成前，Skill 必须先询问选择“Skill 模型（api.apikey.fun）”还是“本地工具”。选择 Skill 模型后，脚本会实时查询 `/v1/models` 并自动选择模型。

## 4. 配置 API Key

每位使用者都应配置自己的 API Key。不要把真实密钥写入 Skill 文件、说明文档或 Git 仓库。

### Windows 用户环境变量

在 PowerShell 中执行：

```powershell
[Environment]::SetEnvironmentVariable(
  "OPENAI_API_KEY",
  "使用者自己的API_KEY",
  "User"
)
```

设置后重新启动 Codex 或终端。

### 临时设置

只在当前 PowerShell 窗口生效：

```powershell
$env:OPENAI_API_KEY = "使用者自己的API_KEY"
```

### 使用 `.env`

可以在项目中保存：

```env
OPENAI_API_KEY=使用者自己的API_KEY
```

同时将 `.env` 加入 `.gitignore`：

```gitignore
.env
```

注意：Skill 的 Node.js 和 Python 脚本不会自动读取 `.env`。手动运行脚本前，需要把 `.env` 中的值加载到 `OPENAI_API_KEY` 环境变量，或者使用 `--api-key` 参数。

## 5. 修改 image-gen 专用 API Key

可以随时更换 image-gen 使用的专用 Key，不需要修改 `SKILL.md`、Node.js 脚本或 Python 脚本。

### 推荐：修改用户级专用 Key

在 PowerShell 中执行：

```powershell

  "OPENAI_API_KEY",
  "新的API_KEY",
  "User"
)
```

修改后重启 Codex 和终端。之后 image-gen 脚本会自动读取新的用户级 `OPENAI_API_KEY`。

```powershell
if ([Environment]::GetEnvironmentVariable("OPENAI_API_KEY", "User")) {

```

只影响当前 PowerShell 窗口，关闭窗口后恢复：

```powershell
$env:OPENAI_API_KEY = "临时API_KEY"
```

这适合临时测试另一个账户、另一个额度或另一个服务端配置。

```env

```

当前 Skill 脚本不会自动解析 `.env`。运行前需要先加载到当前终端：


```powershell

  --api-key "项目专用API_KEY" `
  --out ".\edited.png"
```

### Key 的读取优先级

从高到低为：

1. 当前命令的 `--api-key`。
2. 当前终端的 `$env:OPENAI_API_KEY`。
3. Windows 用户级 `OPENAI_API_KEY`。
4. 未配置时脚本报错，不会自动使用分享者的 Key。

### 更换后的安全检查

- 新 Key 不要写入 `SKILL.md`、`INSTALL.md`、示例脚本或 Git 仓库。
- 不要把 `.env` 放进分享包。
- 更换 Key 后建议撤销旧 Key，避免旧 Key 继续可用。
- 命令历史、终端录屏和日志中也可能留下 `--api-key`，共享前应清理。

### 每次生成前自动获取模型

每次使用 Skill 模型生成前，都必须先使用**刚生效的 Key**向上游获取支持的模型列表，再执行图片或视频任务。不要沿用旧列表，也不要只依据本说明中的示例模型名。

默认 base URL 为 `https://api.apikey.fun/v1`，模型查询请求为：

```powershell
$headers = @{ Authorization = "Bearer $env:OPENAI_API_KEY" }
$models = Invoke-RestMethod `
  -Method Get `
  -Uri "https://api.apikey.fun/v1/models" `
  -Headers $headers

# 只查看模型标识，不输出 API Key
$models.data | Select-Object id
```

如果 base URL 是根地址 `https://api.apikey.fun`，拼接 `/v1/models`；如果 base URL 已包含 `/v1`（`https://api.apikey.fun/v1`），则拼接 `/models`。两种配置最终都应访问 `https://api.apikey.fun/v1/models`，不得拼出重复的 `/v1/v1`。单次命令使用 `--api-key` 时，查询请求的 `Authorization` 必须使用该单次 Key，而不是当前环境变量中的旧 Key。

模型查询应遵循以下流程：

1. 设置或替换 Key，但不要在输出中打印 Key。
2. 使用当前生效的 Key 调用 `GET /models`。
3. 从返回结果中读取模型 `id`，必要时同时读取模型类型、能力或权限字段。
4. 根据任务自动选择：图片优先 `gpt-image-2`、其次 `grok-imagine-image`；480p/720p 视频使用 `grok-imagine-video`；1080p 视频使用 `grok-imagine-video-1.5`。
5. 查询失败时报告上游状态码或非敏感错误信息；在模型支持情况未确认前，不应声称 Key 已验证成功。

可使用 `curl` 等等价 HTTP 客户端完成查询，但必须保留 `Authorization` 请求头，并避免在 shell 历史、日志和聊天记录中泄露完整 Key。

## 10. 上传图片超时排查

上传本地图片时，Codex 可能因为沙箱权限、文件读取限制或网络等待而超时。遇到以下情况时，先检查 Codex 的访问权限：

- 上传图片长时间没有进度。
- 请求在读取本地文件时超时。
- 生图接口连接正常，但图片上传阶段失败。
- 报告 `timeout`、`network_error` 或类似错误。

建议将当前 Codex 会话或项目的访问模式设置为：

```text
完全访问
Full access
```

不同版本的 Codex 入口名称可能略有不同，一般在项目设置、环境设置或权限模式中选择“完全访问（Full access）”。设置后：

1. 保存权限设置。
2. 重启当前 Codex 会话或新开一个终端。
3. 确认源图片路径存在，并且当前用户有读取权限。
4. 重新执行上传或图片编辑命令。

完全访问只解决 Codex 本地读取文件和网络调用的权限问题，不会修复服务端错误，也不会自动延长 API 请求的超时时间。脚本默认超时为 900 秒；排查时可以显式增加：

```powershell
python scripts/python/image_gen.py `
  --mode edit `
  --prompt "保留主体，只删除背景" `
  --image ".\source.png" `
  --timeout 900 `
  --out ".\edited.png"
```

请确认图片上传到 `api.apikey.fun` 已得到图片所有者授权；完全访问模式下尤其不要把不应外传的私人文件放在任务目录中。

## 11. 独立流式接口排查脚本

如果 Skill 命令失败，可以先用下面的最小 Python 脚本验证 API Key、网络、SSE 流和服务端响应。脚本只使用 Python 标准库，必须把 `YOUR_API_KEY` 替换为自己的密钥；不要把真实密钥提交到 Git。

### 10.1 文生图排查脚本

```python
import base64
import json
import urllib.request
from pathlib import Path

API_URL = "https://api.apikey.fun/v1/images/generations"
API_KEY = "YOUR_API_KEY"


def iter_sse(response):
    buffer = ""
    while chunk := response.read(4096):
        buffer += chunk.decode("utf-8", errors="replace")
        frames = buffer.split("\n\n")
        buffer = frames.pop()
        for frame in frames:
            payload = [
                line[5:].strip()
                for line in frame.splitlines()
                if line.startswith("data:")
            ]
            data = "\n".join(payload).strip()
            if data and data != "[DONE]":
                yield data
    # 某些服务端会在最后一个 SSE frame 后直接关闭连接，
    # 因此需要处理没有尾部空行的剩余 buffer。
    if buffer.strip():
        payload = [
            line[5:].strip()
            for line in buffer.splitlines()
            if line.startswith("data:")
        ]
        data = "\n".join(payload).strip()
        if data and data != "[DONE]":
            yield data


body = {
    "model": "gpt-image-2",
    "prompt": "生成一只太空猫",
    "n": 1,
    "size": "1024x1024",
    "stream": True,
    "response_format": "b64_json",
}

request = urllib.request.Request(
    API_URL,
    data=json.dumps(body).encode("utf-8"),
    method="POST",
    headers={
        "Authorization": "Bearer " + API_KEY,
        "Content-Type": "application/json",
        "Accept": "text/event-stream",
    },
)

with urllib.request.urlopen(request, timeout=900) as response:
    for data in iter_sse(response):
        event = json.loads(data)
        if event.get("type") == "image_generation.partial_image":
            print(".", end="", flush=True)
        if event.get("type") == "image_generation.completed":
            image = event.get("b64_json") or (
                event.get("data") or [{}]
            )[0].get("b64_json")
            if not image:
                raise RuntimeError(f"完成事件中没有图片数据：{event}")
            Path("generated-image.png").write_bytes(
                base64.b64decode(image)
            )
            print("\n图片已保存：generated-image.png")
            break
```

运行：

```powershell
python .\stream_generate_debug.py
```

### 10.2 图片编辑 / 参考图排查脚本

这个示例使用 `images[].image_url` 传入参考图，支持公网 HTTPS 图片地址，也支持服务端接受的数据 URL。若直接传本地文件失败，请优先使用 Skill 自带脚本的 `--image` 参数，因为它会按本地文件上传流程处理。

```python
import base64
import json
import urllib.request
from pathlib import Path

API_URL = "https://api.apikey.fun/v1/images/edits"
API_KEY = "YOUR_API_KEY"


def iter_sse(response):
    buffer = ""
    while chunk := response.read(4096):
        buffer += chunk.decode("utf-8", errors="replace")
        frames = buffer.split("\n\n")
        buffer = frames.pop()
        for frame in frames:
            payload = [
                line[5:].strip()
                for line in frame.splitlines()
                if line.startswith("data:")
            ]
            data = "\n".join(payload).strip()
            if data and data != "[DONE]":
                yield data
    if buffer.strip():
        payload = [
            line[5:].strip()
            for line in buffer.splitlines()
            if line.startswith("data:")
        ]
        data = "\n".join(payload).strip()
        if data and data != "[DONE]":
            yield data


body = {
    "model": "gpt-image-2",
    "prompt": "参考这张图，生成一张更精致的科技风品牌图。",
    "images": [
        {"image_url": "https://api.apikey.fun/logo.png"},
    ],
    "n": 1,
    "size": "1024x1024",
    "quality": "auto",
    "stream": True,
    "response_format": "b64_json",
}

request = urllib.request.Request(
    API_URL,
    data=json.dumps(body).encode("utf-8"),
    method="POST",
    headers={
        "Authorization": "Bearer " + API_KEY,
        "Content-Type": "application/json",
        "Accept": "text/event-stream",
    },
)

with urllib.request.urlopen(request, timeout=900) as response:
    for data in iter_sse(response):
        event = json.loads(data)
        image = (
            event.get("b64_json")
            or ((event.get("data") or [{}])[0]).get("b64_json")
            or (event.get("item") or {}).get("result")
        )
        if event.get("type") == "image_generation.partial_image":
            print(".", end="", flush=True)
        if image:
            Path("generated-image.png").write_bytes(
                base64.b64decode(image)
            )
            print("\n图片已保存：generated-image.png")
            break
```

运行：

```powershell
python .\stream_edit_debug.py
```

排查时重点观察：

- HTTP 状态码是否为 `200`。
- 是否能收到 `image_generation.partial_image` 事件。
- 是否收到最终 `image_generation.completed` 事件或包含 `b64_json` 的事件。
- 服务端是否返回 `base64_input_not_supported`、`no_image_result` 或连接中断。

## 14. 透明背景说明

在提示词中明确写：

```text
输出真正带透明 Alpha 通道的 PNG，只保留前景主体。
```

生成完成后应检查文件是否为 `RGBA`，并确认 Alpha 通道同时包含 `0` 和 `255`。

图片生成模型可能会重绘、补全或放大低分辨率输入。若任务要求严格保持每一个原始像素，仅做精确抠图，生成式编辑未必合适。

## 15. 隐私与安全

- 文生图提示词、参考图片和待编辑图片会发送到 `api.apikey.fun`。
- 上传私人图片前，应取得图片所有者授权。
- 不要在聊天记录、脚本、Git 仓库或分享包中包含真实 API Key。
- 不要分享个人 `.env` 文件。
- 每位接收者应使用自己的 API Key。

## 16. 常见问题

### Codex 中找不到 Skill

1. 检查文件是否位于 `%USERPROFILE%\.agents\skills\image-gen`。
2. 检查该目录中是否直接包含 `SKILL.md`。
3. 重启 Codex。
4. 使用 `$image-gen` 显式调用。

### 提示缺少 API Key

确认新终端能读取：

```powershell
if ($env:OPENAI_API_KEY) { "API Key 已加载" } else { "API Key 未加载" }
```

不要输出密钥本身。

### `no_image_result`

接口完成了流式连接，但没有返回最终图片事件。可以稍后重试、简化提示词、降低尺寸，或检查服务端兼容性。

### 编辑结果与原图不完全一致

这是生成式编辑的正常现象。提示词中应明确“不变项”，例如：

```text
保持人物五官、服装、姿势、配色和构图不变，只删除背景。
```
